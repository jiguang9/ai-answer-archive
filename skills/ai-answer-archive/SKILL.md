# AI 回答存档 → 判定 → 原始记录索引

下文 `$SKILL_DIR` 指本 Skill 所在目录（装好后一般是 `~/.claude/skills/ai-answer-archive`，Codex 是 `~/.codex/skills/ai-answer-archive`）。三步都只用 Python 3 / Node 18+ 自带的库，不用装依赖：

| 步骤 | 工具 | 产出 |
|---|---|---|
| 1 存档 | `$SKILL_DIR/tools/archive.py` | `回答存档表.csv`、`原始数据/` |
| 2 判定 | geo-judge 仓库的 `tools/judge-archive.js`（判定代码从它的 `index.html` 读，和网页判定助手同一份） | `判定结果.csv` |
| 3 出索引 | `$SKILL_DIR/tools/build_index.py` | `原始记录索引.csv`、`原始记录索引说明.md` |

列的含义、取数方法、判定口径以仓库 README 为准，不要凭记忆改口径。

## 开工前要问清的

缺什么问什么，一次问完：

1. **链接表**：把用户的链接整理成一个文件。`.csv`（表头含「问题」「第几次」「分享链接」，可选「平台」，例子见 `$SKILL_DIR/examples/链接表-示例.csv`）、`.md` 表格（「题 | AI | 第 1 次 | 第 2 次 …」）、`.txt`（一行一个链接，或「问题 Tab 第几次 Tab 链接」）都行。**问题原文必须一字不差**。ChatGPT 单条分享里没有提问，用户没给问题就回头问，不要猜。
2. **判定设置**：品牌名（多个叫法逗号隔开）、官网域名、竞品（逗号隔开，同一竞品多个叫法用 `|`）。
3. **测试环境**（出索引才要）：账号状态、是否每次新对话、联网、记忆、地区、设备 / 客户端。**用户没说的写「未记录」，不要猜**。
4. **输出放哪**：没指定就在当前目录新建一个以日期和项目命名的文件夹。

## 步骤

```bash
OUT=输出目录

# 1 存档
python3 "$SKILL_DIR/tools/archive.py" 链接表 "$OUT"

# 2 判定（需要 geo-judge，见下）
node "$GEO_JUDGE/tools/judge-archive.js" "$OUT/回答存档表.csv" \
  --brand "品牌, 别名" --domain 官网域名 --competitors "竞品A|别名, 竞品B" \
  -o "$OUT/判定结果.csv"

# 3 出索引：先照 $SKILL_DIR/examples/索引配置-示例.json 写好 "$OUT/索引配置.json"
python3 "$SKILL_DIR/tools/build_index.py" "$OUT" "$OUT/判定结果.csv" "$OUT/索引配置.json"
```

**geo-judge 在哪**：`$GEO_JUDGE` 是 [jiguang9/geo-judge](https://github.com/jiguang9/geo-judge) 的本地副本。本机没有的话，先征得用户同意再 `git clone --depth 1 https://github.com/jiguang9/geo-judge`。用户不想下载，就让用户打开 [在线判定助手](https://aimarketinglift.com/tools/geo-judge)，第 3 步点「导入存档表（CSV）」选 `回答存档表.csv`，判完点「下载 CSV」，把文件放回输出目录当 `判定结果.csv`。两种方式判出来的结果逐字节一致。

**索引配置**：字段有 `项目`、`问题集来源`（问题集有没有和委托方确认、封存，照实写）、`判定工具`、`判定设置`、`环境`（`通用` 加各平台）、`限制`（时间窗口数、每题次数、有没有做交叉验证和独立抽样复核、有没有人工复核，照实写）。

## 每步跑完要看的

- **存档**：终端最后一行「成功 N，要人打开看 M」。M 不为 0 时，把每条的平台、问题、原因列给用户。豆包「任务模式」生成的文件只能用户去账号里下载；链接打不开的请用户核对。**失败的不删、不补，照实留在表里**。
- **判定**：终端会打出各状态条数和跳过的行。抽 1–2 条「正文提及」到 `回答存档表.csv` 看正文确实点了名；有「仅被引」的，看来源列表里那条是不是官网、是不是标了「正文引用」。
- **索引**：看 `原始记录索引说明.md` 的数量核对；抽一条用 `shasum -a 256 原始数据/文件`（Windows：`certutil -hashfile 文件 SHA256`）核对和索引里的哈希一致。

## 交付给用户时说清楚

- 一句话：几条、成功几条、各状态几条、哪些要人打开看。
- 交付物是整个输出目录：`原始记录索引.csv`、`原始记录索引说明.md`、`回答存档表.csv`、`原始数据/`。
- 限制照实说：时间窗口不够 3 个、样本少、没做交叉验证时，索引只能当基线或演示，不能当效果证明（047 第 8.3、8.1、12.3 条）。

## 不要做的

- 不调用任何 AI 接口，不替用户去 AI 里提问；只请求分享链接本身。
- 只处理用户自己的、或用户有权处理的分享链接。
- 不编造环境信息、档位、问题原文。分享数据里没有的就写没有。
- 原始数据只隐去分享者昵称、头像和账号 ID（`archive.py` 自动做），其余原样，不改。
- 输出里除了链接，不写其他个人信息。

## 目前做不到的

- 只支持豆包、ChatGPT（`chatgpt.com/s/…` 单条分享）、DeepSeek；其他平台的链接会标「要人打开看：暂不支持」。ChatGPT 老式整段分享（`/share/…`）没拿真实样本测过。
- 豆包分享数据读不到档位；ChatGPT 分享数据里没有搜索词。
- 各家分享页和分享接口都不是公开 API，随时可能改；取不到时会标「要人打开看」，不会悄悄漏掉。
- DeepSeek 分享网页在有些网络下会被拦，分享数据接口能正常取。
